# Shellbit

Фронтенд для ретро-эмуляторов на Godot 4.6 (GDScript). Сейчас — **этап 1**: интерфейс, библиотека игр и запуск игр через ядра libretro.

## Как запустить

1. Открой Godot 4.6 → **Import** → выбери файл `project.godot` из этой папки.
2. Нажми **F5** (или ▶ в правом верхнем углу).
3. Нажми «+ Папка с играми» и выбери папку с ROM-файлами (.nes, .sfc, .md, .gba…).

Управление: стрелки / крестовина / стик — перемещение, **A / Enter** — выбрать, **B / Esc** — назад,
**Y / F** — избранное, **LB RB / Q E** — другая приставка, **X / Tab** на главном — пересканировать папки.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `autoload/Settings.gd` | Настройки (файл `user://settings.cfg`) |
| `autoload/Lang.gd` | Язык интерфейса, переводы из `data/i18n/strings.tsv`, числа со словами |
| `autoload/CoreManager.gd` | Список приставок из `data/systems.json` |
| `autoload/Library.gd` | Поиск игр, недавние, избранное (`user://library.json`) |
| `autoload/InputMapper.gd` | Свои действия ввода, определение типа геймпада, раскладка кнопок по приставкам |
| `autoload/UiTheme.gd` | Цвета, шрифты, стиль кнопок и рамки фокуса |
| `autoload/SceneRouter.gd` | Переходы между экранами, «Назад», всплывающие сообщения |
| `scenes/home/` | Главный экран |
| `scenes/library/` | Экран одной приставки |
| `scenes/components/` | Карточка игры, плитка приставки, строка подсказок, рисунок геймпада (`PadView.gd`) |
| `scenes/settings/` | Настройки и экран «Кнопки приставок» (`PadMapScreen`) |
| `data/pads.json` | Геймпады приставок: кнопки, их раскладка по умолчанию и как их рисовать |
| `scenes/player/` | Экран игры: картинка, звук, кнопки |
| `native/` | C++-модуль RetroCore (исходники + godot-cpp) |
| `addons/shellbit_core/` | Собранный модуль (.dll) и его описание для Godot |

`user://` в Windows — это `%APPDATA%\Shellbit`, в Linux — `~/.local/share/Shellbit`
(своё имя папки задано в `project.godot`: `use_custom_user_dir`).
Раньше данные лежали в `%APPDATA%\Godot\app_userdata\Shellbit`: при первом запуске новой версии
Shellbit сам копирует их на новое место и оставляет в старой папке файл «ДАННЫЕ ПЕРЕЕХАЛИ.txt» —
после проверки старую папку можно удалить.

## Запуск и сборка — двойным щелчком

| Файл | Что делает |
| --- | --- |
| `Run.bat` | Запускает Shellbit из проекта, не открывая редактор |
| `Build.bat` | Собирает готовую программу в `build\Shellbit\` (`Shellbit.exe`, `Shellbit.pck` и `.dll` модуля) |
| `Test.bat` | Запускает автотесты из папки `test\` (около минуты) |
| `Publish.bat` | Тесты → сборка → архив для раздачи `dist\Shellbit-<версия>-windows.zip`. Упал тест — выпуска нет |
| `native\build.bat` | Собирает C++-модуль (обычно его вызывает `Build.bat` сам) |

- При первом запуске `tools\godot.bat` попросит перетащить в окно файл Godot (`Godot_v4.7.2-stable_win64.exe`)
  и запомнит путь в `godot_path.txt`. Godot переехал — удалите этот файл.
- Для `Build.bat` нужны **шаблоны экспорта**: в Godot — Редактор → Управление шаблонами экспорта → Загрузить и установить.
- Если нет release-версии C++-модуля, `Build.bat` сначала соберёт её — **Godot должен быть закрыт**.
- Версия программы — `application/config/version` в `project.godot` (её же видно в «О программе»).
  Перед новым выпуском поменяйте её, и `Publish.bat` назовёт архив по ней.
- Настройки экспорта лежат в `export_presets.cfg`: там уже прописаны иконка `icon.ico`
  и фильтр файлов, которые не являются ресурсами Godot
  (`data/*.json, data/covers/*.txt, data/meta/*.txt, data/i18n/*.tsv, *.ico`). Новый тип таких файлов — добавьте его туда.


## Linux и Steam Deck

Всё то же самое есть в виде `.sh`-файлов — для CachyOS, другого Linux и Steam Deck:

| Файл | Что делает |
| --- | --- |
| `Run.sh` | Запускает Shellbit из проекта |
| `Build.sh` | Собирает программу в `build/Shellbit-linux/` (`Shellbit.x86_64`, `Shellbit.pck`, `.so` модуля) |
| `Test.sh` | Автотесты |
| `Publish.sh` | Тесты → сборка → архив `dist/Shellbit-<версия>-linux.tar.gz` |
| `native/build.sh` | Собирает C++-модуль под Linux (`build.sh release` — для готовой программы) |

**Один раз перед первой сборкой** (CachyOS / Arch):

```
sudo pacman -S --needed base-devel cmake ninja python git
```

- Файлы можно запускать двойным щелчком в Dolphin — они сами откроют окно Konsole.
  Если Dolphin вместо запуска открывает файл в редакторе — файлу не хватает пометки
  «программа»: правой кнопкой → Свойства → Права → **«Является исполняемым»**
  (или в терминале: `chmod +x *.sh native/build.sh`).
- Godot ищется в системе (`godot` после `sudo pacman -S godot`), потом в «Загрузках»
  (`Godot_v4.7.2-stable_linux.x86_64`), иначе его попросят перетащить в окно терминала.
  Путь запоминается в `godot_path_linux.txt` — у Windows свой файл, они не мешают друг другу.
  **Версия Godot должна совпадать с проектом (4.7.2)** — версия из pacman может быть другой.
- Данные программы: `~/.local/share/Shellbit` (ядра — в `cores/`, BIOS — в `system/`),
  скриншоты — `~/Изображения/Shellbit` (или `~/Pictures/Shellbit`).
- Ядра в Linux — `…_libretro.so`, Shellbit скачивает их сам так же, как в Windows.
- Для игр в `.7z` нужен 7-Zip из системы: `sudo pacman -S 7zip`. Архивы `.zip` работают без него.

**Steam Deck.** Скопируйте папку `Shellbit` из архива (`Publish.sh`) на Deck, в режиме
рабочего стола добавьте `Shellbit.x86_64` в Steam: «Добавить игру» → «Добавить стороннюю игру».
После этого Shellbit запускается и из игрового режима. Модуль собирается со встроенной
стандартной библиотекой C++ (`-static-libstdc++`), чтобы не зависеть от её версии на Deck.

## Автотесты

Папка `test\`: каждый файл `test_*.gd` — набор тестов, каждая функция `test_…` — один тест.
`Test.bat` запускает их и пишет итог: ✓ — прошёл, ✗ — упал (и что именно не так).

- Тесты работают во временной папке данных (`%TEMP%\shellbit-tests`) — ваши настройки,
  библиотека и сохранения не трогаются. Без `Test.bat` запускалка отказывается работать.
- Тест падает и тогда, когда во время него в коде случилась ошибка (обращение к null и т.п.).
- Что проверяется: таблица переводов (все языки, `%s`/`%d` в том же порядке, у каждого
  русского текста из кода и сцен есть перевод), разбор имён ROM и файлов описаний,
  раскладки кнопок и `pads.json`, настройки и переезд данных, поиск игр (на файлах-пустышках
  из `test\fixtures\roms`), ускорение и перемотка (на ненастоящем ядре `MockCore.gd`),
  а также что все экраны открываются на всех 9 языках.
- Новый тест: добавьте функцию `test_что_то()` в подходящий файл или новый файл `test\test_….gd`
  (`extends TestCase`). Проверки: `check(…)`, `check_eq(получилось, ожидали)`, `check_has(…)`.

## Этап 1: сборка C++-модуля (Windows, один раз)

1. **Visual Studio Build Tools 2022 или новее** (бесплатно): https://visualstudio.microsoft.com/downloads/ →
   «Build Tools for Visual Studio». В установщике отметь **«Разработка классических приложений на C++»**
   (Desktop development with C++). Справа проверь, что отмечены **MSVC**, **Windows SDK** и **C++ CMake tools for Windows**.
2. **Python 3**: https://www.python.org/downloads/ — при установке поставь галочку **«Add python.exe to PATH»**.
3. **Закрой Godot**, затем дважды щёлкни `native/build.bat`. При первом запуске он сам скачает библиотеку godot-cpp
   в `native/godot-cpp`, сборка идёт 5–15 минут. Временные файлы сборки лежат в `%LOCALAPPDATA%\Shellbit-build`.
4. В папке `addons/shellbit_core/bin/` появится `shellbit_core.windows.template_debug.x86_64.dll`.

## Ядра libretro

Ядро — это готовый эмулятор одной приставки. Shellbit скачивает ядра сам, одной кнопкой:

- **Настройки → Ядра и BIOS → «Скачать недостающие ядра»** — все сразу (по два одновременно);
- там же A на строке приставки с пометкой «Скачать» — одно ядро;
- на экране «Не удалось запустить игру» — кнопка **«Скачать ядро»**: скачает и сразу запустит игру.

Ядра берутся с официального сервера libretro — оттуда же их скачивает RetroArch:
`https://buildbot.libretro.com/nightly/windows/x86_64/latest/<ядро>.dll.zip`
(в Linux — `linux/x86_64/…/.so.zip`). Код — `autoload/CoreDownloader.gd`.
Архив распаковывается в папку ядер `%APPDATA%\Shellbit\cores`; туда же можно положить `.dll` и вручную.
Какое ядро нужно какой приставке — поле `default_core` в `data/systems.json`.

BIOS не скачиваются: это программы самих приставок, их нужно положить в папку BIOS самим.

## Игры в архивах (.zip, .7z)

Игры можно хранить в архивах: `Contra (USA).zip` с файлом `Contra (USA).nes` внутри.
Код — `autoload/Archives.gd`.

- **Какая приставка** — Shellbit узнаёт по файлу внутри архива (`.nes` → NES, `.cue` → PS1).
  Если знакомых файлов нет, это архив аркадного автомата (FBNeo читает его сам, без распаковки).
- **Перед запуском** архив распаковывается в `%APPDATA%\Shellbit\cache\roms`. Повторный запуск
  берёт уже распакованное. Если кеш больше 4 ГБ, давно не запускавшиеся игры из него удаляются
  (архивы на месте — распакуются снова). Сохранения от этого не зависят.
- **.zip** Godot читает сам. Для **.7z** нужен 7-Zip: в Windows Shellbit сам скачивает
  консольный `7zr.exe` (600 КБ) с официального сайта https://www.7-zip.org в `%APPDATA%\Shellbit\tools`,
  когда впервые встречает `.7z`. В Linux нужна программа `7z`/`7zz` из системы (пакет p7zip или 7zip).

### Nintendo 64 и аппаратная отрисовка

Ядро Nintendo 64 (`mupen64plus_next`) рисует не само, а через видеокарту (OpenGL 3.3).
Shellbit создаёт для него отдельный невидимый OpenGL-контекст (`native/src/gl_context.cpp`:
в Windows — WGL, в Linux и на Steam Deck — EGL), ядро рисует в него, а готовый кадр
читается обратно и показывается как обычно. Нужен драйвер видеокарты с OpenGL 3.3 —
у любой карты последних ~12 лет он есть. Если не получилось, экран игры так и скажет.
Нужен свежий `shellbit_core` (`native\build.bat`). Ядра на Vulkan (ParaLLEl-N64, PS2) — пока нет.

### PlayStation 1

- Ядро: **`pcsx_rearmed_libretro.dll`**. Работает и без BIOS (встроенная замена), но с настоящим BIOS
  совместимость выше: положи свой дамп `scph5501.bin` в `%APPDATA%\Shellbit\system`.
- Форматы игр: `.cue` (рядом с ним лежат `.bin`), `.chd`, `.pbp`, `.m3u`.
- **Многодисковые игры** (Final Fantasy VII, Metal Gear Solid…). Когда игра просит вставить
  следующий диск — меню паузы → **«Сменить диск»** → выбрать диск. Shellbit «откроет крышку»,
  сменит диск и «закроет» её, как на настоящей приставке.
  - Если файлы называются по правилам — `… (Disc 1).cue`, `… (Disc 2).cue` — ничего делать
    не нужно: Shellbit сам составит список дисков (`.m3u`) в своей папке `cache/m3u`,
    папку с играми он не трогает.
  - Можно и свой `Название (USA).m3u` — текстовый файл, где по строке перечислены `.cue` всех дисков.
    Тогда он станет основной версией игры («все диски»).
  - Сохранения помнят, на каком диске их сделали (`states/<…>/discs.json`): «Продолжить»
    после выхода на втором диске сразу вставит второй диск.
  - Работает и с многодисковыми `.pbp`. Нужен свежий `shellbit_core` (`native\build.bat`).
- Сохранения внутри игры (карта памяти) лежат в `...\Shellbit\saves\<имя игры>.srm`.

## Управление в игре

| Геймпад | Клавиатура | RetroPad |
| --- | --- | --- |
| Крестовина / левый стик | Стрелки | Крестовина |
| A (нижняя) | Z | B |
| B (правая) | X | A |
| X (левая) | A | Y |
| Y (верхняя) | S | X |
| LB / RB | Q / W | L / R |
| Start / Back | Enter / Shift | Start / Select |
| **Правый стик (нажать)** или **View + Menu** | **Esc** | Меню паузы |
| **Share** (Xbox Series, PS5) или «Скриншот» в меню паузы | **F12** | Скриншот → `Изображения\Shellbit` |
| — | **F11** или **Alt+Enter** | Полный экран ↔ окно (запоминается; ещё — Настройки → Видео → Режим окна) |

Это раскладка **по положению**: нижняя кнопка геймпада Xbox — нижняя кнопка
приставки (B у SNES), правая — правая (A у SNES).

### Своя раскладка для каждой приставки

**Настройки → Управление → Кнопки приставок.** Слева — кнопки приставки,
справа — рисунок её геймпада и вашего (Xbox или PlayStation): на кнопках вашего
геймпада написано, какая кнопка приставки на них стоит. LB / RB — другая приставка.

- **A** на строке → «Нажмите кнопку…» → нажмите кнопку геймпада. Через 5 секунд или по Esc — отмена.
- **◀ ▶** — перебрать кнопки геймпада по списку.
- Если кнопка геймпада уже занята, две кнопки приставки **меняются местами**.
- У NES, SNES и Game Boy есть готовая раскладка **по надписям**: A на A, B на B.

Раскладки хранятся в `user://settings.cfg`, раздел `[pads]` — только то, что вы поменяли.
Клавиатура и крестовина не переназначаются; правый стик — всегда меню паузы.

**Стики.** У PlayStation и Nintendo 64 стики уходят в игру как настоящие
стики — чуть наклонил, персонаж идёт, до упора — бежит. У PlayStation
Shellbit сам «вставляет» в приставку DualShock. У Nintendo 64 левый стик —
это стик приставки (на клавиатуре — стрелки), правый — C-кнопки.
У остальных приставок стиков не было, там левый стик нажимает крестовину.
Для стиков нужен свежий `shellbit_core.dll` — пересоберите его через
`native\build.bat` (со старым игры работают, но без стиков).

### Ускорение и перемотка назад

| Что | Геймпад (по умолчанию) | Клавиатура |
| --- | --- | --- |
| Перемотка назад (держать) | LT | Backspace |
| Ускорение (держать или нажать — см. настройки) | RT | Пробел |

У PlayStation и Nintendo 64 курки нужны самой игре (L2/R2, Z), поэтому там
перемотка — **Back + LT**, ускорение — **Back + RT**: сначала зажать Back, потом курок.
Пока Back зажат вместе с курком, ни Back (Select), ни курки в игру не уходят.
Можно и назначить отдельную кнопку в «Кнопках приставок».
Скорость (×2…×8), режим кнопки и длина перемотки — **Настройки → Игра**.

### Звук без щелчков (синхронизация по звуку)

Часы компьютера и звуковой карты идут чуть по-разному, и без подстройки звук
то кончается (щелчок), то переполняет буфер (тоже щелчок). Shellbit держит буфер
звука заполненным на 40% и чуть-чуть, не больше чем на ±0,5%, растягивает
или сжимает звук — как «dynamic rate control» в RetroArch. Если буфер почти пуст
или почти полон, досчитывается лишний кадр или пропускается один.
Код — `scripts/AudioSync.gd`, задержка звука — около 35 мс. Если звук всё же
прерывался, при выходе из игры в Output будет строка «Звук прерывался N раз».

### Эмуляция в отдельном потоке

Кадры приставки, звук и снимки перемотки считаются в своём потоке
(`Player._emulation_loop`), а главный поток только рисует интерфейс и читает кнопки.
Если интерфейс подвис (открылось меню, система подгружает что-то с диска),
игра не замедляется. Ядро защищено замком (`_core_lock`): сохранение, загрузка
и смена диска ждут, пока поток досчитает кадр.

### Настройки ядра

Меню паузы → **«Настройки ядра»**: всё, что умеет настраивать ядро этой приставки
(регион, улучшения графики, карты памяти…). Список присылает само ядро, поэтому
названия обычно по-английски; если у ядра есть перевод, Shellbit попросит его
на языке интерфейса. ◀ ▶ — поменять, B — назад, внизу — «Вернуть всё как было».
Настройки с пометкой (Restart) заработают после «Начать заново».
Хранятся в `settings.cfg`, в разделе `[core_<имя ядра>]` — только изменённые,
общие для Windows и Linux. Код — `scenes/player/CoreOptionsPanel.gd`.
Нужен свежий `shellbit_core` (`native\build.bat`).

### Вибрация

Если игра умеет вибрацию, геймпад вибрирует: PlayStation (игры с поддержкой
DualShock), картриджи Game Boy и Game Boy Advance с моторчиком.
Выключается в **Настройки → Игра → Вибрация**. На паузе и во время перемотки
геймпад не вибрирует. Нужен свежий `shellbit_core.dll` (`native\build.bat`).

Как это устроено (`scenes/player/Player.gd`, раздел «Ускорение и перемотка»):
- **ускорение** — за один кадр экрана просчитывается несколько кадров приставки;
- **перемотка** — каждые 2 кадра игра делает быстрое сохранение (`save_state`)
  на «ленту»; пока кнопка зажата, снимки загружаются с конца ленты.
  Лента занимает не больше `Settings.REWIND_BUDGET_MB` (256 МБ): у тяжёлых
  приставок снимки делаются реже.

Какие кнопки у каждой приставки и как они нарисованы, описано в `data/pads.json`
(подсказка по полям — в начале файла). Там же можно поправить раскладку по умолчанию.

## Сохранения

- **Меню паузы:** продолжить, начать заново, 3 слота сохранений, выйти в библиотеку.
- На слоте: **A** — загрузить (в пустой — сохранить), **X** — сохранить сюда.
- При выходе игра **сохраняется сама**, а при следующем запуске продолжается с того же места.
- Файлы лежат в `%APPDATA%\Shellbit\states\` — своя папка для каждого файла игры.

## Жанры

Shellbit узнаёт жанр игры по папке, в которой она лежит:

```
D:/Game_archive/NES(Famicom)/Platformer/Mega Man 2/Mega Man 2 (USA).nes
                 приставка    жанр       папка игры
```

В библиотеке, справа от сортировки, — кнопка **«Все жанры ▾»**. В её списке
только жанры, которые есть у этой приставки, и сколько в каждом игр.
Открыть список — кнопка **View** на геймпаде (⧉, слева от кнопки Xbox;
на PlayStation — Share/Create) или **G** на клавиатуре. С клавиатуры до кнопки
можно дойти и стрелками: из поля поиска — вправо (когда курсор в конце текста).
Выбранный жанр остаётся при переходе на другую приставку (**LB/RB**):
смотрел платформеры NES — на SNES тоже покажутся платформеры.

Какие имена папок считаются жанрами — список `LIST` в `scripts/Genres.gd`
(английские имена вроде `Platformer`, `RPG`, `Beat 'em Up`, `Board, Card & Mahjong`
и русские вроде `Платформеры`). Большие буквы, пробелы, `'`, `&` и запятые
не важны. Папки `_Unsorted` и другие не-жанры просто не совпадают —
такие игры попадают в «Без жанра». Новая папка-жанр — допиши её имя в нужную строку.

На странице игры жанр по папке показывается вместо жанра из базы.

### Если переложить игры в другие папки

Shellbit узнаёт файл по полному пути. Если игру переложили (или чуть
переименовали — пробелы, скобки), при следующем поиске он сам находит её
на новом месте по имени файла и переносит туда: избранное, время в игре,
выбранную версию, слоты сохранений, карту памяти ядра (`.srm`).
Сравниваются только буквы и цифры имени: `Atlantis(FullRus)Лисы.chd` =
`Atlantis (FullRus) Лисы.chd`. Если одинаковых имён несколько
(`Batman (U).nes` из двух сборников), какую куда — не угадать, такие не трогаются.
Код — `_carry_over_moved()` в `autoload/Library.gd`.

## Обложки

Обложки скачиваются сами из бесплатного архива [libretro-thumbnails](https://github.com/libretro-thumbnails)
(сначала с thumbnails.libretro.com, при ошибке — с GitHub) и хранятся в `%APPDATA%\Shellbit\covers\`.
Указатели `data/covers/<приставка>.txt` («ключ игры → имя обложки») собраны заранее из этого архива.
Если игры нет в архиве, на карточке остаётся название текстом.

**Свои обложки** (важнее скачанных):
- положи картинку с тем же именем рядом с игрой: `Adventures of Donald Duck.gb` → `Adventures of Donald Duck.png`
  (подходят `.png`, `.jpg`, `.jpeg`, `.webp`);
- или на экране приставки нажми **Start / Menu** (F1) → «Выбрать свою обложку…». Там же — «Убрать свою обложку».

**Большие коллекции.** Сетка игр «виртуальная» (`scenes/components/VirtualGrid.gd`):
карточек в ней ровно столько, сколько видно на экране, при прокрутке они переезжают
и показывают другие игры. Обложки читаются с диска в фоновом потоке, в памяти
держится не больше 300 последних (`Covers.MAX_TEXTURES`). Экран приставки
с 2000 игр открывается примерно за 0,2 с.

## Страница игры

В библиотеке **A** открывает страницу игры: обложка, год, жанр, число игроков, разработчик
(из открытой базы [libretro-database](https://github.com/libretro/libretro-database), собраны в `data/meta/`),
время в игре и сохранения. Отсюда можно запустить игру с места выхода или с любого слота.

## Описание игры

Описание пишется в текстовом файле **рядом с игрой, с тем же именем** и расширением `.txt`
(кодировка UTF-8): `Battletoads (U) [!].nes` → `Battletoads (U) [!].txt`.
Если у игры несколько версий, файл достаточно положить рядом с любой из них.

В одном файле можно держать текст на нескольких языках:

```
[ru]
title: Боевые жабы
Три жабы-космонавта летят спасать подругу Энджику и принцессу
из плена Тёмной королевы.

Знаменита своей сложностью — особенно уровень с гонками на байках.

[en]
Three space toads set out to rescue their friend from the Dark Queen.

[ja]
title: バトルトード
宇宙のカエル3匹が、ダーククイーンから仲間を救い出す。
```

- `[ru]`, `[en]`, `[zh]`, `[ja]`, `[de]`, `[fr]`, `[es]`, `[pt]`, `[ko]` — с этой строки начинается текст на этом языке.
- `title:` (или `название:`) — необязательная первая строка раздела: название игры на этом языке.
  Показывается на странице игры вместо названия из имени файла.
- Всё остальное — описание. Пустые строки (абзацы) сохраняются.
- Какое описание показать: **язык интерфейса → английский → русский → текст без метки**.
  Например, если японского раздела нет, японец увидит английский текст.
- Название (`title:`) берётся только на языке интерфейса или английское; если его нет —
  показывается название из имени файла.
- **Старые файлы без меток** продолжают работать: весь текст считается описанием для любого языка.

Разбирает файл функция `GameInfo.parse_description()` в `scripts/GameInfo.gd`.

## Языки интерфейса

Языки: русский, английский, китайский (упрощённый), японский, немецкий, французский,
испанский, португальский (Бразилия) и корейский.
Язык меняется в **Настройки → Язык**: A на строке «Язык интерфейса» открывает список. «Как в системе» — язык Windows.

- Все переводы — в таблице `data/i18n/strings.tsv` (столбцы `ru  en  zh  ja  de  fr  es  pt  ko`, разделитель — табуляция).
  Её удобно править в LibreOffice Calc или Excel: открыть как «текст с разделителями-табуляциями»,
  сохранить в том же формате и в кодировке UTF-8.
- Первый столбец — русский текст, он же ключ: в коде пишется `tr("Настройки")`.
  Новый текст в коде → добавить строку в таблицу.
- `\n` в таблице — перенос строки. `|` разделяет формы слова для чисел: `%d игра|%d игры|%d игр`
  (в европейских языках две формы, в китайском, японском и корейском — одна).
  Правила, какую форму брать, — в `Lang._plural_index()`.
- Новый язык: добавить столбец в таблицу, код языка — в `Lang.SUPPORTED` и `Lang.CHOICES`,
  при необходимости — шрифт в `UiTheme.FONTS` и правило чисел в `Lang._plural_index()`.
- Для китайского, японского и корейского Shellbit сам берёт шрифты Windows (Microsoft YaHei, Yu Gothic, Malgun Gothic).
